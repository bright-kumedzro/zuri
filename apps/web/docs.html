Using Zuri

@brightkumedzro/zuri-avatar turns any string (a user ID, an email, a name) into a unique 3D avatar. The same string always gives the same face, so there is nothing to upload, store or sync. Everything is generated from code in the browser with three.js.

There are three styles, and the same seed gives the same person in all of them:

  • Toon 3D: an animated-film look with big expressive eyes and sculpted, glossy hair. Same outputs as 3D. See Toon 3D.
  • 3D: live in a canvas (it blinks, sways and can be rotated), as a PNG/WebP/JPEG image, or as a .glb model for Blender, Unity and AR.
  • Flat 2D: a vector illustration as a small SVG string. It needs no WebGL, so it also works on servers, in emails and in native apps. See Flat 2D avatars.

Full-body characters and realistic digital humans are planned.

Not a developer? Use the builder to design a face and download it as a PNG or .glb, no code needed.

Install

For 3D, install the package with three.js (version 0.170 or newer):

npm i @brightkumedzro/zuri-avatar three

For flat 2D avatars only, you don't need three.js:

npm i @brightkumedzro/zuri-avatar

The package ships ES modules with TypeScript types. The 3D mesher runs in Web Workers that are built into the package, so there is nothing to configure in Vite, webpack, Next.js or any other bundler.

Quick start

Show a live avatar in a canvas:

<canvas id="avatar" width="256" height="256"></canvas>

<script type="module">
  import { AvatarFactory, AvatarStage } from "@brightkumedzro/zuri-avatar";

  const stage = new AvatarStage({ canvas: document.getElementById("avatar"), transparent: true });
  stage.setSize(256, 256);
  stage.show(await new AvatarFactory().create("ada@example.com"));
  stage.render();
</script>

Or get an image you can put in any <img>:

import { AvatarFactory, snapshotAvatar } from "@brightkumedzro/zuri-avatar";

const zuri = new AvatarFactory();
const avatar = await zuri.create(user.id);
img.src = snapshotAvatar(avatar, { size: 256 });

Live 3D on a page

AvatarStage is a ready-lit scene with a camera that frames the avatar. Give it a canvas, size it, show an avatar and call render every frame to animate the idle blinks and sway. 

import { AvatarFactory, AvatarStage } from "@brightkumedzro/zuri-avatar";

const canvas = document.querySelector("canvas");
const stage = new AvatarStage({ canvas, transparent: true });
stage.setSize(canvas.clientWidth, canvas.clientHeight);
stage.frame("head");                          // or "bust" (default)
stage.show(await new AvatarFactory().create("kwame"));

function loop(ms) {
  stage.render(ms / 1000);                     // time in seconds drives blinks and sway
  requestAnimationFrame(loop);
}
requestAnimationFrame(loop);

Calling show again swaps in a new avatar and frees the old one. Call setSize whenever the canvas changes size (a ResizeObserver works well), and stage.dispose() when you remove the canvas.

To let people rotate the avatar, change stage.avatar.rotation.y from pointer events. The avatar is a normal THREE.Group.

Images (PNG, WebP)

snapshotAvatar renders an avatar facing forward with its eyes open and returns a data URL. All snapshots share one offscreen renderer, so taking many is cheap. 

import { AvatarFactory, disposeAvatar, snapshotAvatar } from "@brightkumedzro/zuri-avatar";

const zuri = new AvatarFactory();

async function avatarUrl(seed, size = 96) {
  const avatar = await zuri.create(seed, { quality: 0.75 });
  const url = snapshotAvatar(avatar, { size, type: "image/webp", quality: 0.9 });
  disposeAvatar(avatar);                       // free GPU memory once you have the image
  return url;
}

Render at twice the displayed size for sharp images on high-density screens (a 48 px avatar needs size: 96). Pass transparent: true to drop the coloured background.

To save a file, turn the data URL into a download link, or fetch(url).then(r => r.blob()) to upload it.

In a three.js scene

If you already have a scene, add the avatar to it like any other object. It is about 3.5 units tall from shoulders to hair, with the head near the origin, facing +Z. Your scene needs lights; MeshPhysicalMaterial looks best with an environment map. 

import { AvatarFactory } from "@brightkumedzro/zuri-avatar";

const avatar = await new AvatarFactory().create("ada");
avatar.position.set(0, 1.5, 0);
scene.add(avatar);

renderer.setAnimationLoop((ms) => {
  avatar.userData.tick(ms / 1000);           // idle blinking + sway
  renderer.render(scene, camera);
});

When you remove it, call disposeAvatar(avatar) to free its geometries, materials and textures.

Customising traits

Every avatar starts from its seed, and any option you pass overrides that one trait. Everything else stays the same, so a user keeps their face when they change their hair. 

const avatar = await zuri.create(user.id, {
  hair: "locs",
  skin: 2,                    // index into SKIN_TONES (0 = deepest) or a hex like "#8b563a"
  expression: "grin",
  outfit: "hoodie",
  glasses: "round",
  background: "#cde2f7",
});

To let users personalise their avatar, store only the options they changed next to their ID, for example { "hair": "locs" }, and pass them back in. See AvatarOptions for every value.

Toon 3D

Pass style: "toon" for an animated-film look: a bigger, rounder head, large eyes with big catchlights, sculpted brows, chunky glossy hair and smooth skin. It's the same person as the default "soft" style, and everything else (live 3D, images, .glb, every trait option) works the same way. 

const avatar = await zuri.create(user.id, { style: "toon", hair: "afro" });
img.src = snapshotAvatar(avatar, { size: 256 });

createAvatar and renderAvatarImage accept style too.

Wardrobe

Any avatar can wear any garment, in every style. Pass outfit to choose one, and outfitColor and accentColor (as #rrggbb) to recolor it. The accent colors ties, bows, trims, buttons and scarves. 

const avatar = await zuri.create(user.id, {
  outfit: "kente",
  accessory: "headtie",        // a gele, in the avatar's print colors
});

const doctor = await zuri.create(user.id, { outfit: "labcoat", accentColor: "#2f5d8a" });

Accessories go on top: accessory: "scarf", "necklace" or "headtie" (which covers the hair). Some garments have their own default color, like a white lab coat or blue denim; outfitColor overrides it.

Faces generated from a seed only ever wear the original seven tops. Everything else is opt-in, so new clothes never change an existing user's avatar. WARDROBE lists every garment with its category, for building your own picker.

Exporting .glb

Use three.js's GLTFExporter to save an avatar as a binary glTF file:

import { GLTFExporter } from "three/addons/exporters/GLTFExporter.js";

const avatar = await zuri.create("hiro");
const glb = await new GLTFExporter().parseAsync(avatar, { binary: true });
const url = URL.createObjectURL(new Blob([glb], { type: "model/gltf-binary" }));

The file includes the painted face texture and materials. Idle animation is not exported.

Flat 2D avatars

The flat style draws the same traits (skin tone, hair, outfit, expression, glasses and so on) as a vector illustration. It returns an SVG string of about 4 KB, runs anywhere JavaScript does, and doesn't need three.js. Import it from @brightkumedzro/zuri-avatar/flat to keep three.js out of your bundle. 

import { createFlatAvatar, flatAvatarDataURL } from "@brightkumedzro/zuri-avatar/flat";

const svg = createFlatAvatar(user.id, { size: 96, shape: "circle" });
img.src = flatAvatarDataURL(svg);              // or insert the SVG markup directly

Every AvatarOptions override works here too, plus size, transparent and shape ("square", "rounded" or "circle"). See createFlatAvatar.

On a server

// Express, Next.js route handlers, Cloudflare Workers… anything that can return text.
app.get("/avatars/:id.svg", (req, res) => {
  res.type("image/svg+xml").set("Cache-Control", "public, max-age=31536000, immutable");
  res.send(createFlatAvatar(req.params.id, { size: 256 }));
});

Because the same ID always gives the same picture, these responses can be cached forever. In the browser, rasterizeSVG(svg, { size: 512 }) turns the SVG into a PNG data URL when you need a bitmap.

React, Vue and others

Zuri has no framework dependency. Create one AvatarFactory for the whole app and use images for lists and profile pictures. Use live 3D only for the one or two avatars that need it.

React

import { useEffect, useState } from "react";
import { AvatarFactory, disposeAvatar, snapshotAvatar } from "@brightkumedzro/zuri-avatar";

const zuri = new AvatarFactory();

export function Avatar({ seed, size = 48 }) {
  const [src, setSrc] = useState();
  useEffect(() => {
    let live = true;
    zuri.create(seed, { quality: 0.75 }).then((a) => {
      if (live) setSrc(snapshotAvatar(a, { size: size * 2 }));
      disposeAvatar(a);
    });
    return () => { live = false; };
  }, [seed, size]);
  return <img src={src} width={size} height={size} alt="" />;
}

Vue

<script setup>
import { ref, watchEffect } from "vue";
import { AvatarFactory, disposeAvatar, snapshotAvatar } from "@brightkumedzro/zuri-avatar";

const props = defineProps({ seed: String, size: { type: Number, default: 48 } });
const src = ref();
const zuri = new AvatarFactory();
watchEffect(async () => {
  const a = await zuri.create(props.seed, { quality: 0.75 });
  src.value = snapshotAvatar(a, { size: props.size * 2 });
  disposeAvatar(a);
});
</script>

<template><img :src="src" :width="size" :height="size" alt="" /></template>

Svelte, Angular, Solid and plain JavaScript follow the same pattern: create the avatar, take a snapshot, put it in an <img>. With server-side rendering (Next.js, Nuxt, SvelteKit), only call Zuri in the browser, for example inside useEffect or onMount, because it needs WebGL and Web Workers.

Performance

  • Reuse one factory. Each AvatarFactory starts its own worker pool (up to 4 workers).
  • Lower the quality for small images. quality: 0.75 is noticeably faster and looks the same at thumbnail sizes.
  • Cache images. The same seed always gives the same picture, so you can keep data URLs in memory or localStorage.
  • Dispose. Call disposeAvatar on avatars you no longer show, and factory.dispose() to stop the workers.
  • Limit live canvases. Every AvatarStage owns a WebGL context, and browsers allow only about 16 at once.

API reference

createAvatar(seed, options?)

createAvatar(seed: string, options?: AvatarOptions & { quality?: number }): Avatar

Builds an avatar synchronously on the main thread. Simple, but it blocks for tens of milliseconds, so prefer AvatarFactory in apps.

AvatarFactory

new AvatarFactory(options?: { workers?: number })

Builds avatars on a pool of Web Workers. workers defaults to your CPU cores minus one, at most 4. Pass 0 to build on the main thread. Without Worker support, it falls back to the main thread automatically.

MethodDescription
create(seed, options?)Returns Promise<Avatar>. Accepts all AvatarOptions plus quality and style.
build(params, quality?)Builds from AvatarParams you got from generateAvatar (and possibly edited).
dispose()Stops all workers.

renderAvatarImage(seed: string, options?: AvatarOptions & SnapshotOptions): string

Builds, snapshots and disposes in one call on the main thread. Handy for one image; for many, use AvatarFactory and snapshotAvatar.

generateAvatar(seed, options?)

generateAvatar(seed: string, options?: AvatarOptions): AvatarParams

Returns the plain-data description of an avatar (skin, face shape, eyes, hair, outfit, expression and so on) without building anything. It needs no WebGL, so it also runs on a server. Useful for showing trait names, or for editing a field and passing the result to factory.build(params). 

import { generateAvatar } from "@brightkumedzro/zuri-avatar/params";

generateAvatar("ada").hair.style;              // e.g. "curly"

The Avatar object

An avatar is a THREE.Group with a few extras on userData:

FieldDescription
userData.paramsThe AvatarParams it was built from.
userData.tick(t)Advance the idle animation to time t in seconds.
userData.topThe y position of the top of the hair, for framing.

Free it with disposeAvatar(avatar) when you're done.

Determinism

The seed is hashed into a random number generator, and each group of traits (identity, shape, style, mood) uses its own stream. So overriding one trait never changes the others, and the same seed gives the same face on every device and browser.

Seeds are case-sensitive: "Ada" and "ada" are different faces. Normalise them (for example, lower-case emails) before passing them in. Every result carries params.version, which only changes in a release that alters existing faces.

Privacy

The library runs entirely in the browser and makes no network requests, so no personal data leaves the device. If you would rather not use emails as seeds, hash them first; the avatar is just as unique. 

const bytes = await crypto.subtle.digest("SHA-256", new TextEncoder().encode(email.toLowerCase()));
const seed = [...new Uint8Array(bytes)].map((b) => b.toString(16).padStart(2, "0")).join("");

Hosted API coming soon

A hosted image API is planned for apps that can't run WebGL, such as emails, native apps and server rendering. Avatars will be plain URLs, cached on a CDN:

https://api.zuri.dev/avatar/{seed}.glb

It isn't live yet. Email us to hear when it is.

Troubleshooting

The canvas is blank.
Call stage.setSize() with non-zero values, then stage.render(). Nothing draws until you render.
The avatar looks black in my own scene.
Add lights, or an environment map such as three.js's RoomEnvironment. AvatarStage sets these up for you.
Avatars build slowly, or the console mentions a Content Security Policy.
The workers start from a blob: URL. If your CSP blocks that, Zuri falls back to the main thread, which works but can stutter. Add worker-src blob: to your policy to keep the workers.
"window is not defined" or "document is not defined".
The code ran on the server. Only build and render 3D avatars in the browser. generateAvatar and the flat style (@brightkumedzro/zuri-avatar/flat) work anywhere.
The browser warns about too many WebGL contexts.
Use images for lists, keep live stages to a few, and call stage.dispose() when you remove one.
